# VITHELO Gummies Concept 01 产品详情页设计规范

日期：2026-09-20  
状态：已通过视觉方向确认，待用户书面确认后进入实施计划

## 1. 真实问题

当前产品详情页只有基础画廊、参数、折叠信息和询盘按钮，能够展示资料，但不足以形成完整的 B2B 产品判断路径。本轮只改造 `gummies-concept-01`，用一个完整样板验证产品详情页的视觉、内容与询盘结构，不批量改造其他产品。

## 2. 目标与边界

### Must

- 目标地址：`/products/gummies?product=gummies-concept-01`。
- 建立完整长页：首屏、定制能力、项目路径、决策系统、审核状态、包装方向、制造与质量、FAQ、询盘收口。
- 借鉴用户提供的 Seed DS-01 页面在比例、层级、留白和长页节奏上的机制。
- 保持 VITHELO 的冷 Ivory、Graphite、Titanium 与克制 Optical light 视觉体系。
- 所有现有产品数据继续标记为 `DEMO_ONLY` 或“待生产核验”。
- 保留 Email 与 WhatsApp 的直接询盘路线，不增加站内提交、支付或购买。
- 桌面、平板、手机、键盘与 Reduced Motion 状态均可完整使用。

### Should

- 首屏建立与参考页相近的“大影像 + 紧凑信息栏”比例。
- 让页面既有消费级产品表现力，又能帮助 B2B 买家理解项目需要确认什么。
- 将产品、定制、制造和询盘串成一条连续叙事，而不是独立卡片集合。

### Could

- 在数据模型允许时，为其他产品复用同一结构。
- 在获得正式资料后替换演示参数、包装方向和制造证据。

### Won't

- 不复制 Seed 的品牌、绿色视觉、产品图、文案、功效、临床表达、订阅、价格、评论或购买逻辑。
- 不改造其他 79 个演示产品。
- 不改首页、产品列表页、导航设计或其他已接受页面。
- 不新增未经核验的成分、功效、剂量、认证、MOQ、交期、价格或法规结论。
- 不连接 CRM、服务端表单、支付、分析或身份系统。

## 3. 参考页机制的 VITHELO 转译

本轮借鉴的是结构与体验机制，不是品牌外观或业务内容：

| Seed 参考机制 | VITHELO 转译 |
| --- | --- |
| 大幅产品影像 + 右侧购买栏 | 大幅产品影像 + 右侧项目简报与询盘入口 |
| 功效与产品卖点 | 可定制决策与产品开发要素 |
| 效果时间轴 | 从 Brief 到 Packaging 的项目决策路径 |
| 配方与成分说明 | Formula、Sensory、Form、Packaging 四项联动 |
| 产品对比表 | 已选方向与仍需确认输入的审核状态表 |
| 月度配送 | 包装方向与货架呈现 |
| 测试标准 | 制造适配、过程检查和成品文件讨论边界 |
| FAQ | 项目输入、定制、制造与包装 FAQ |
| 购买与评论 | Email / WhatsApp 直接询盘收口 |

## 4. 页面结构

### 4.1 首屏：产品影像与项目简报

- 桌面采用约 `72 / 28` 的双栏比例。
- 左栏为大尺寸产品影像，低圆角，影像承担主要视觉重量。
- 右栏为紧凑的项目信息栏，包含：
  - `GUMMIES · CONCEPT 01`
  - 产品名称
  - 一段不含功效承诺的概念说明
  - 来源与生产核验边界
  - `Start a Project` 主 CTA
  - 明确说明价格、MOQ、交期与生产结论尚未确认
  - Project parameters、Customization options、Manufacturing review 折叠区
- 右栏在桌面可在首屏范围内保持可读；手机端回到普通文档流，不做黏性覆盖。

### 4.2 定制能力场景

- 使用一张完整生活方式影像作为背景。
- 标题为 `Shape the product around your brief.`。
- 底部使用一块半透明能力层，展示 Formula Direction、Taste + Texture、Shape + Color、Pack + Count。
- 文字必须在无图片或 Reduced Motion 状态下仍可直接阅读。

### 4.3 项目决策路径

- 使用纵向时间轴表达 Brief、Feasibility、Sample、Packaging 四个阶段。
- 时间轴不承诺交期，只说明每一阶段承担的判断任务。
- 右侧使用产品或使用场景影像平衡信息密度。

### 4.4 四项联动决策

- 展示 Formula、Sensory、Form、Packaging 四项相互关联的开发决策。
- 使用两张产品细节图与四列决策条，不把演示信息包装成已确认生产事实。

### 4.5 项目审核状态表

- 深色背景承接页面节奏。
- 表格区分“已选择的概念方向”与“生产前仍需确认的输入”。
- 不做 VITHELO 与竞争品牌的优劣比较，不构造性能、认证或市场优势。

### 4.6 包装方向

- 使用一主两次的影像构图，呈现 bottle、label expression 与 product detail 等方向。
- 所有当前包装画面保持 `DEMO_ONLY`。

### 4.7 制造与质量

- 使用浅色背景和三块等权信息区。
- 仅表达当前已允许的边界：制造适配审查、过程检查对齐、成品文件讨论。
- 不展示未核实认证图标或测试结论。

### 4.8 FAQ

- 桌面采用左侧大标题、右侧折叠列表。
- FAQ 只回答项目输入、可定制范围、制造适配审核和包装讨论路径。
- 默认展开一个对买家最有帮助的问题，其余保持折叠。

### 4.9 询盘收口

- 使用独立色块形成清晰的终点。
- 标题为 `Bring the brief. We’ll review the route.`。
- CTA 引导至已配置的直接询盘能力。
- 不显示虚假成功状态，也不在站内保存或提交数据。

## 5. 视觉系统

- 页面背景以冷 Ivory 为主，文本使用 Graphite。
- 深色段落使用接近 Titanium / Graphite 的中性深色，不复制 Seed 墨绿色。
- Optical light 只用于少量能力层与询盘收口，不形成绿色营养频道。
- 标题使用现有项目字体系统，强调宽松留白与大字号，不引入 Seed 字体。
- 圆角用于大影像、信息容器与 CTA；避免泛化为圆角卡片网格。
- 页面节奏依靠影像尺度、背景明暗和段落高度建立，不依赖装饰性渐变或过度阴影。

## 6. 内容与数据流

- 页面继续从现有内容层读取 `gummies-concept-01` 数据。
- 只为该产品增加本页所需的结构化内容记录；不把产品事实写死在路由或页面组件中。
- 新字段必须通过 Zod 合同和内容适配边界进入组件。
- 缺失值保持 `DEMO_ONLY` 或 `NOT_CONFIGURED`，不能生成合理化占位事实。
- 当 URL 中不存在或无法识别 `product` 参数时，保持现有剂型详情回退，不显示本样板的专属长页内容。

## 7. 组件边界

- `VitheloDosageFormDetail` 负责解析当前产品并选择详情页组合。
- 样板页拆为若干职责单一的局部组件：Hero、Capability Scene、Project Timeline、Decision System、Review Matrix、Packaging Direction、Quality Review、FAQ、Inquiry Close。
- 共享的展示原语复用现有 Core、Motion 和 Token 层；不新增页面级任意颜色或时长。
- 本轮不为单一页面建立过度通用的页面生成框架。

## 8. 交互与动效

- 动效只用于内容揭示和状态确认，不做滚动劫持。
- 首屏影像不做跟随指针或强制视差。
- FAQ 与首屏折叠区支持键盘操作、明确焦点和 `aria-expanded`。
- Reduced Motion 直接显示最终状态；任何重要事实不依赖动画出现。
- 询盘 CTA 最小触控尺寸为 44px，并有可见焦点。

## 9. 响应式行为

- 桌面：首屏双栏、场景能力层四列、时间轴双栏、FAQ 双栏。
- 平板：首屏保留双栏但压缩排版；能力与质量区允许两列换行。
- 手机：首屏改为影像在上、信息在下；所有信息进入正常文档流；表格允许语义化纵向重排，不产生横向滚动。
- 所有验收视口不得出现文本裁切、覆盖、水平溢出或固定元素遮挡内容。

## 10. 状态与失败行为

- 图片缺失：显示明确的 `DEMO_ONLY · AWAITING APPROVED VISUAL` 占位，而不是空白或错误图标。
- 产品参数缺失：显示核验边界，不生成推断值。
- 未知产品参数：回退到通用 Gummies 剂型详情。
- JavaScript 不可用：产品信息、关键边界和联系入口仍可阅读与到达。
- 直接 `#contact`、键盘焦点和 Reduced Motion 不得被装饰性过渡阻挡。

## 11. 验证与验收

### 自动验证

- 为 `gummies-concept-01` 专属长页增加组件测试与内容合同测试。
- 验证其他产品仍使用现有详情页路径，不被样板结构污染。
- 验证 FAQ 键盘交互、`aria-expanded`、焦点可见性和 CTA 可达性。
- 在六个验收视口检查响应式、横向溢出、图片回退和 Reduced Motion。
- 运行定向 lint、typecheck、unit、E2E 和 build；完整回归结果需与项目当前已知旧断言失败区分记录。

### 视觉验收

- 首屏必须保留“大影像 + 紧凑信息栏”的参考关系。
- 长页必须呈现连续叙事，而不是普通圆角卡片合集。
- 不出现 Seed 品牌、绿色视觉、产品逻辑或可识别文案复制。
- P0 = 0、P1 = 0 后，由用户完成本产品页最终视觉确认。

## 12. 成功标准

用户进入 `gummies-concept-01` 后，能够依次回答：

1. 这是什么产品概念？
2. 哪些部分可以讨论和定制？
3. 项目需要经过哪些判断？
4. 哪些信息已经选择，哪些仍待确认？
5. 制造与质量目前能承诺到什么边界？
6. 如何直接发起询盘？

页面同时保持 VITHELO 品牌独立性，不把 Seed 的消费电商和临床功效逻辑带入 B2B 制造网站。
