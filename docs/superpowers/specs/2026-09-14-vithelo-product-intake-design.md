# VITHELO 产品资料采集与本地入站设计规范

日期：2026-09-14
状态：已完成方案确认，待用户复核书面规范

## 1. 目标

把一个包含多款产品的 Excel 文件转换为可追溯的 VITHELO 产品档案和网站内容。系统先自动整理与校验，再生成待确认预览；只有用户确认后，才把内容和图片写入本地独立站并打开页面预览。

本流程不自动推送 GitHub，也不触发 Hostinger 部署。

## 2. 范围

### Must

- 在 `E:\观澜\02-跨境业务\VITHELO\产品资料\` 提供可直接填写的多产品 Excel 模板。
- 自动读取 Excel，按稳定产品编号拆分产品，不能只靠产品名称猜测对应关系。
- 自动生成 Obsidian 产品档案、问题清单和网站写入预览。
- 在写入网站前设置一次明确的用户确认闸门。
- 用户确认后，把产品记录写入网站内容层，把获准使用的图片放入对应产品目录，并运行定向验证。
- 保留来源、证据、公开许可和缺失状态；不得自动补写产品功效、认证、剂量、价格、MOQ、交期或法规结论。

### Should

- 支持同一 Excel 中多款产品、多行参数、多张图片和多条宣称/证据。
- 对重复产品生成字段级差异，不静默覆盖既有档案或网站内容。
- 使用受控剂型词表，把产品映射到当前产品入口与详情页。
- 生成简洁的中文审核摘要和英文网站内容预览。

### Could

- 后续支持批量图片嵌入提取、其他表格结构映射、CMS 或远程发布。

### Won't（第一版不做）

- 不监听文件夹并无条件自动发布。
- 不自动推送 GitHub，不触发 Hostinger 正式上线。
- 不建设 CMS、数据库、CRM 或内部表单提交系统。
- 不照搬参考网站的品牌、绿色视觉、价格、评分、订阅或临床宣传。
- 不重新设计已锁定的首页或其他已验收页面。

## 3. 参考页面的取舍

用户提供的两张截图仅作为产品详情页的信息组织参考，不作为事实来源、品牌素材或复制指令。

保留的结构机制：

- 左侧主图与缩略图图库。
- 右侧产品名称、短描述、关键参数和询盘按钮。
- 下方分组展示产品说明、定制方向、包装、配方/成分和证据边界。
- 适合 B2B 买家快速判断的产品规格密度。

不采用的内容：

- Seed 品牌、深绿色视觉、零售价格、评分、订阅和组合购。
- 参考站的品牌标识、产品图、文案、临床或功效结论。
- 面向消费者直接成交的购买逻辑。

VITHELO 页面继续使用现有 Ivory、Graphite、Titanium 与 Optical light 视觉体系，并以 OEM / ODM 询盘为转化目标。

## 4. 知识库目录

在 Obsidian 知识库建立：

```text
E:\观澜\02-跨境业务\VITHELO\产品资料\
├── VITHELO产品资料采集模板.xlsx
├── 产品资料工作流.md
├── 待整理\
├── 待确认\
├── 产品档案\
└── 已入站\
```

- `待整理`：用户放入的原始 Excel 与配套图片；原始文件不修改。
- `待确认`：每次导入生成的审核摘要、错误清单和网站预览。
- `产品档案`：用户确认后的标准 Obsidian 产品笔记。
- `已入站`：完成本地网站写入后的源文件归档；保留原文件名和导入批次。
- `产品资料工作流.md`：填写说明、受控词表、命令示例和状态定义。

新建的正式知识库页面遵守 `E:\观澜\宪法.md`：使用中文文件名、完整 frontmatter、至少两个 wikilink，并同步更新 `00-首页.md` 与 `99-系统\变更日志.md`。

## 5. Excel 工作簿结构

工作簿包含四张业务表和一张说明表。所有表使用 Excel Table，冻结首行并提供下拉选项。空白模板带一款明确标记为“示例，不导入”的示范产品。

### 5.1 `填写说明`

说明必填项、产品编号规则、剂型词表、公开状态、图片文件组织和常见错误。该表不参与导入。

### 5.2 `产品主表`

一行代表一款产品。

| 字段 | 必填 | 用途 |
|---|---:|---|
| `导入状态` | 是 | `正式资料` 或 `示例不导入` |
| `产品编号` | 是 | 全局稳定键；用于更新和关联其他工作表 |
| `剂型` | 是 | 受控词表，映射网站 format slug |
| `英文产品名` | 是 | 网站标题候选 |
| `中文内部名` | 否 | 知识库识别，不直接公开 |
| `英文短描述` | 是 | 产品卡及详情页摘要候选 |
| `产品类型` | 否 | 例如 dietary supplement；只记录来源中明确内容 |
| `口味` | 否 | 未提供则保持空白 |
| `配方方向` | 否 | 不把配方方向改写成功效结论 |
| `净含量` | 否 | 保留原单位与原文 |
| `每包装数量` | 否 | 与净含量分开记录 |
| `包装形式` | 否 | bottle、pouch、sachet 等 |
| `颜色/外观` | 否 | 仅记录可验证描述 |
| `储存条件` | 否 | 不使用模板默认值代替来源事实 |
| `保质期` | 否 | 必须有来源；否则为空 |
| `定制方向` | 否 | 例如 formula、flavor、shape、packaging |
| `目标市场` | 否 | 用于审核，不自动推导合规性 |
| `公开许可` | 是 | `可公开`、`仅内部`、`待确认` |
| `来源文件` | 是 | 原始 Excel、规格书或其他文件名 |
| `来源页/位置` | 否 | 工作表、行号或文档页码 |
| `备注` | 否 | 内部信息，不直接公开 |

剂型受控值与当前网站映射：

| Excel 值 | 网站 slug |
|---|---|
| Gummies | `gummies` |
| Jelly | `jelly` |
| Hard Capsules | `hard-capsules` |
| Tablets | `tablets` |
| Powders | `powders` |
| Softgels | `softgels` |
| Liquids | `liquids` |
| Oral Films | `oral-films` |

无法映射的剂型进入错误清单，不自动归入 `other`。

### 5.3 `产品参数`

一行代表一个可展示参数，允许同一产品拥有任意数量的参数。

| 字段 | 必填 | 用途 |
|---|---:|---|
| `产品编号` | 是 | 关联产品主表 |
| `参数名称英文` | 是 | 网站参数标签 |
| `参数值英文` | 是 | 网站参数值 |
| `参数名称中文` | 否 | 内部审核辅助 |
| `参数值中文` | 否 | 内部审核辅助 |
| `排序` | 是 | 控制展示顺序 |
| `公开许可` | 是 | `可公开`、`仅内部`、`待确认` |
| `来源文件` | 是 | 事实来源 |
| `来源页/位置` | 否 | 便于复核 |

### 5.4 `图片清单`

一行代表一张图片。首版以“Excel 文件旁的配套图片文件 + 表内文件名”作为稳定输入；如果图片只嵌在 Excel 中，系统可以提取候选图，但在待确认预览中要求人工确认产品归属。

| 字段 | 必填 | 用途 |
|---|---:|---|
| `产品编号` | 是 | 关联产品 |
| `图片文件名` | 是 | 相对于 Excel 所在目录或其同名素材文件夹 |
| `图片用途` | 是 | `主图`、`悬浮图`、`包装图`、`场景图`、`细节图`、`标签/规格图` |
| `排序` | 是 | 图库顺序 |
| `英文替代文本` | 否 | 缺失时只生成待补项，不猜测功效或场景 |
| `图片来源` | 是 | 拍摄者、供应商或来源文件 |
| `使用许可` | 是 | `可公开`、`仅内部`、`待确认` |
| `备注` | 否 | 裁切、背景或质量问题 |

系统拒绝把来源不明或未获公开许可的图片写入公开媒体目录。

### 5.5 `宣称与证据`

一行代表一条候选公开表述及其证据边界。此表是审核表，不是自动文案生成池。

| 字段 | 必填 | 用途 |
|---|---:|---|
| `产品编号` | 是 | 关联产品 |
| `候选表述英文` | 是 | 待审核原文 |
| `候选表述中文` | 否 | 内部理解辅助 |
| `表述类型` | 是 | `产品描述`、`成分事实`、`规格事实`、`功效宣称`、`认证/质量`、`其他` |
| `证据文件` | 否 | 规格书、检测报告、证书等 |
| `证据页/位置` | 否 | 精确定位 |
| `适用主体与范围` | 否 | 产品、批次、工厂、市场或时间范围 |
| `限制条件` | 否 | 不适用范围或不确定性 |
| `公开许可` | 是 | `可公开`、`仅内部`、`待确认` |
| `审核结论` | 是 | `可采用`、`仅作内部参考`、`证据不足`、`待核验` |

只有同时满足“公开许可 = 可公开”和“审核结论 = 可采用”的行，才可进入网站写入预览。功效、认证与法规相关内容即使满足这两个字段，也必须在预览中单独列出，等待本次用户确认。

## 6. 产品档案格式

每款产品生成 `产品档案\<产品编号>-<中文内部名或英文短名>.md`，包含：

- 身份与剂型映射。
- 原始字段与英文网站候选字段。
- 参数、图片、宣称和证据的关联表。
- 缺失字段、冲突和风险项。
- 最近一次导入批次和网站写入状态。
- 到产品资料工作流及 VITHELO 项目页的 wikilink。

产品档案是审核与追溯载体，不直接等同于公开网页。

## 7. 自动整理与确认流程

```text
多产品 Excel + 配套图片
        ↓
结构检查、字段规范化、产品编号关联
        ↓
来源/许可/证据检查 + 图片检查
        ↓
生成产品档案草稿、问题清单、字段级差异
        ↓
生成网站写入预览（不改网站）
        ↓
用户一次确认
        ↓
写入本地内容层与 public/media/products/<产品编号>/
        ↓
Schema、单元测试、类型检查、定向页面检查
        ↓
打开本地产品页预览
```

一次确认只覆盖预览中列出的产品、字段、图片和目标位置。确认后如果源 Excel 又发生变化，必须重新生成差异并再次确认。

## 8. 网站内容映射

当前产品详情使用 `/products/[剂型]?product=<产品编号>`。首版保留这个路由，不新增独立产品 slug 路由，也不重构首页。

网站数据从现有大体量 demo 夹具中拆出独立的产品目录记录，通过 Zod schema 解析后合并到产品发现与详情页；页面组件只消费解析后的数据，不直接保存业务事实。

| Excel/档案 | 网站位置 |
|---|---|
| 产品编号 | product `id` 与查询参数 |
| 剂型 | `formatSlug` 与 `/products/[剂型]` |
| 英文产品名 | 产品卡与详情页 `title` |
| 英文短描述 | `descriptor` 与详情摘要 |
| 产品参数 | 右侧规格表 |
| 主图、悬浮图、其他图片 | 产品卡和详情图库 |
| 获准公开的描述/事实 | 下方信息分组 |
| 未确认或缺失内容 | 不公开，保留在档案问题清单 |

媒体目录使用 `public/media/products/<产品编号>/`，文件名规范化但保留原文件与转换映射记录。公开图片的替代文本只写可观察内容和产品身份，不加入未经证实的功效。

## 9. 数据状态与覆盖规则

- 原始 Excel 和配套文件视为不可变来源，不在导入过程中修改。
- 知识库状态使用：`待整理`、`待确认`、`已确认`、`已入站`、`有阻塞`。
- 网站现有 `DEMO_ONLY` 记录不能仅因 Excel 导入就静默变为已核实事实。
- 获准公开且具备来源的普通产品规格可以写入候选生产记录；证据不足的字段继续缺省或保持明确的演示/未配置状态。
- 同一产品编号已存在时，默认执行更新预览；名称相同但编号不同视为潜在重复并阻止自动写入。
- 同一产品编号对应多个剂型时阻止导入，要求修正来源。

## 10. 自动化技能

新增可自动发现的个人技能 `vithelo-product-intake`，安装在标准技能目录 `E:\CodexWorkspace\codex-home\skills\vithelo-product-intake\`。知识库中的工作流页面负责告诉用户如何触发；技能负责：

1. 找到用户指定的 Excel 或 `待整理` 中的新文件。
2. 校验工作簿结构并生成标准化中间结果。
3. 生成 Obsidian 待确认档案和网站差异预览。
4. 明确询问一次写入确认。
5. 确认后调用确定性的导入脚本写入本地网站。
6. 运行验证并返回本地预览地址与变更文件清单。

技能不得把“整理资料”的请求当成“确认写入”，也不得把“写入本地”扩大为 GitHub 推送或生产部署。

## 11. 错误处理

下列情况停止网站写入，但仍生成问题清单：

- 缺少产品编号、剂型、英文产品名或英文短描述。
- 子表引用不存在的产品编号。
- 产品编号重复且字段冲突。
- 剂型无法映射或与网站既有记录冲突。
- 图片文件不存在、格式不支持、归属不明或没有公开许可。
- 功效、认证、法规、剂量等高风险表述缺少证据位置或审核结论。
- 预览生成后源文件发生变化。

单个产品出错时，默认允许其他无错误产品继续生成预览；用户确认时可选择只写入无错误产品。任何失败都不应产生半写入状态。

## 12. 验证与验收

### 模板与导入器

- 空白模板能打开，五张表、表头、下拉和示例行完整。
- 一个工作簿可包含至少三款不同剂型产品，并正确拆分关联数据。
- 缺失必填字段、孤立子表行、重复编号和未知剂型会产生可理解的错误。
- 未公开许可的图片与表述不会进入网站候选数据。
- 重复导入相同文件不产生无意义变更。

### 知识库

- 新页面 frontmatter、wikilink、首页索引和变更日志符合知识库宪法。
- 原始 Excel 保持不变，导入批次和来源可追溯。

### 网站

- 产品通过 Zod 内容契约进入页面，不在路由或组件中硬编码事实。
- 产品正确出现在对应剂型产品列表和详情页。
- 图片顺序、替代文本、参数顺序和询盘 CTA 正确。
- 键盘操作、44px 目标、Reduced Motion 和现有页面锁定不受破坏。
- 运行产品相关单元测试、`pnpm.cmd typecheck`、定向 ESLint 和生产构建。
- 打开桌面与移动端本地预览；不得出现裁切、溢出、遮挡或错误产品映射。

## 13. 完成定义

第一版完成时，用户可以把包含多款产品的 Excel 和配套图片放入知识库，要求 Codex 自动整理，查看一份明确的待确认预览，并在一次确认后把通过校验的产品写入 VITHELO 本地网站对应剂型与产品详情位置。流程不需要手工复制字段，不会未经确认发布，也不会把缺失或未核验内容伪装成公开事实。
