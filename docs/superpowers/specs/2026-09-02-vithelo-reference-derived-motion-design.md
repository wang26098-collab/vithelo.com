# VITHELO 参考动效提炼重构设计规范

> 状态：设计已确认，待实施计划与代码落地。
>
> 参考来源：`E:\Hermes work\ai-web\index.html`。只提炼其动效机制，不复制页面视觉、内容结构、绿色品牌风格或未经核验的公开陈述。

## 一、目标

在不重做页面视觉、不改动公开文案、不破坏首页七屏结构的前提下，重构 Project-12 VITHELO 独立站的动效语言。新方案把参考 HTML 中有效的遮罩揭示、分批进入、数字启动与导航响应，转换为 VITHELO 已定义的 `SCALE × REVEAL × RESPONSE`，并为每种动作声明 `ORIENT`、`RELATE`、`EXPLAIN`、`FOCUS` 或 `CONFIRM` 意图。

成功标准不是“动画更多”，而是不同内容类型拥有不同且可解释的运动方式；任何内容在脚本失败或 Reduced Motion 下仍完整可见。

## 二、范围

### Must

- 重构首页共享的视口进入运行器，保留一次触发、离开后不重播。
- 将当前全站统一的 `opacity + translateY(44px)` 拆成标题、媒体、证据、集合和流程五种语义动作。
- 为 Reduced Motion 提供静态优先路径，不让默认 CSS 隐藏内容。
- 保持 Hero 背景图绝对静止，不缩放、不位移、不遮罩、不视差。
- 覆盖桌面与移动端，避免动画制造横向溢出、点击延迟或阅读等待。

### Should

- 制造证明数字只在首次进入视口时启动一次。
- 软糖能力、八种剂型和 OEM / ODM 路径拥有各自的分批节奏。
- Email、WhatsApp、导航和主要按钮具备快速、可中断的状态反馈。
- 保留测试可识别的 `data-motion-intent`、`data-motion-state` 与 Reduced Motion 标记。

### Could

- 在不增加依赖的前提下，为局部静态媒体加入轻量裁切揭示。
- 在流程线条或证据分隔线中使用一次性的方向展开。

### Won't

- 不修改 Hero 图片、首页结构、页面文案、事实数据或内容适配器。
- 不引入滚动劫持、装饰性视差、持续漂浮、弹跳缓动或循环动画。
- 不给每一屏套同一种淡入上移动画。
- 不新增动画依赖；继续使用现有 CSS、React 与浏览器观察能力。

## 三、动效命题

### 主场动作

首页第二屏“制造证明”承担整站唯一的重点编排：屏幕进入阅读区后，标题建立方向，生产媒体以短距离裁切展开，证据分隔结构随后显现，数字按阅读顺序启动一次。该动作表达“从品牌印象进入可核对的制造证据”，而不是装饰性开场。

### 连续性

- 导航只解释顶部与滚动态之间的状态变化，不做品牌重动画。
- 产品方向继续使用原生纵向滚动关系，不增加横向控制、页码或吸附式滚动。
- 页面区块离开视口后保持最终状态，回滚时不重复表演。

### 反馈

- 链接与按钮在 150–240ms 内完成颜色、边框或小幅位移反馈。
- 键盘焦点保持清晰，不以动画替代 focus ring。
- Inquiry 操作不等待进入动画即可点击。

### 性能预算

- 常规动作只使用 `transform` 与 `opacity`。
- 裁切只用于少量静态媒体或结构线，避免大面积 blur、filter 与阴影动画。
- 每组交错总延迟桌面不超过 420ms，移动端不超过 240ms。
- 不持久设置 `will-change`；不动画 `width`、`height`、`top`、`left` 或外边距。

## 四、页面动作映射

### 1. Hero — ORIENT

- 背景图保持现有最终样式和静态位置。
- Hero 文案与操作区可在首次装载时使用一次 500–700ms 的低位移进入。
- 不增加图片遮罩、缩放或延迟用户操作的整屏编排。

### 2. Manufacturing proof — ORIENT + EXPLAIN

- 标题先于证据层进入，但不使用冗长等待。
- 静态生产媒体使用参考 HTML 的遮罩思路，改为符合当前冷 Ivory / Graphite / Titanium 视觉的裁切揭示。
- 数字从静态真实终值或可安全增强的起始状态启动；脚本失败时直接显示终值。
- 未核验事实的来源边界与标签始终可见，不能被动画延后或弱化。

### 3. Gummy capability — RELATE

- 图片先建立场域，功能条目按视觉邻近关系分批出现。
- 动作强调“媒体与能力说明属于同一制造能力”，不做漂浮卡片或循环动效。

### 4. Product directions — RELATE

- 维持现有原生纵向滚动和移动端顺序阅读。
- 当前方向仅改变局部强调状态；其他方向仍可见，不把事实藏入非激活面板。
- 不增加横向轮播、页码、左右箭头或滚动劫持。

### 5. Product formats — RELATE

- 标题与说明作为一个编辑式组进入。
- 八种剂型作为同一完整集合揭示，采用短时行列交错，不把 Oral Films 单独强调。
- 移动端缩短间隔，避免访客等待最后几个剂型出现。

### 6. OEM / ODM runway — EXPLAIN

- 流程骨架先建立，六个步骤沿实际阅读方向依次确认。
- 动画只解释顺序，不改变步骤文案的文档顺序和可访问性。
- 质量检查点始终可读，不依赖线条或节点动画表达。

### 7. Inquiry close — CONFIRM

- 区块内容默认可见，不设置进入等待。
- Email 与 WhatsApp 只使用快速 hover、focus、active 状态反馈。
- 不恢复无效表单，不连接未授权的 CRM、分析或提交服务。

## 五、共享实现边界

- 继续由首页客户端动效运行器统一管理 `IntersectionObserver`，避免每屏创建独立观察器。
- DOM 默认保持最终可读状态；仅在浏览器支持观察器且未开启 Reduced Motion 时，在首次绘制后的增强阶段设置 `data-motion-enabled`。
- 每个动作通过数据属性或有限的语义类选择，不允许页面代码传入任意时长和位移。
- 数字增强逻辑与内容值解耦：读取已验证渲染值，不在组件内硬编码事实。
- 观察器完成一次触发后立即 `unobserve`，组件卸载时 `disconnect`。
- SSR、无 JavaScript、IntersectionObserver 不可用和 Reduced Motion 均直接呈现完整终态。

## 六、时序

- 即时反馈：150ms。
- 常规状态：240ms。
- 内容关系揭示：约 500ms。
- 第二屏重点编排：单个动作不超过 900ms，整体不因串行动画阻塞阅读。
- 统一使用自然减速曲线；不使用 bounce、elastic 或 overshoot。
- 退出状态若存在，必须快于进入；首页一次性视口动画默认不设置退出动画。

## 七、Reduced Motion

- 取消位移、缩放、裁切与数字滚动。
- 内容、证据、媒体、流程和询盘操作直接显示最终状态。
- hover、focus、active 仍可保留短时颜色或边框反馈，以便确认交互状态。
- 禁用 smooth scrolling 和非必要动画循环。
- Reduced Motion 不得改变页面高度、内容顺序或重要信息的可见性。

## 八、验证与验收

### 自动验证

- 单元测试覆盖：一次触发、观察器缺失、Reduced Motion、卸载清理和数字终值保留。
- E2E 覆盖：桌面与移动端触发状态、Hero 图片无 transform、八种剂型完整可见、Inquiry 可立即操作。
- 现有 `lint`、`typecheck`、`test`、`test:e2e` 与 `build` 通过。

### 视觉验证

- 在六个项目验收视口一次性检查桌面与移动端。
- P0 = 0、P1 = 0；无裁切错误、重叠、横向溢出或滚动卡顿。
- 动效节奏可辨识但不过度重复；移除任一动作时，应能指出失去的方向、关系、解释或反馈意义。
- 用户对本次动效重构进行明确视觉签收。

## 九、已知约束

- 当前工作区存在大量与本任务无关的未提交改动；实施必须只触碰动效运行器、必要的首页样式、相关组件标记和测试。
- 参考 HTML 含有与当前公开内容边界冲突的绿色视觉、未核验陈述和表单示例；这些内容不是迁移范围。
- 当前第二屏视觉仍处于单屏验收阶段。动效实现必须适配其已批准的 `V-A Editorial Proof Ledger`，不得借动效任务重新设计该屏。
