# VITHELO OEM / ODM Nordicus 视觉修订设计规范

日期：2026-09-20  
状态：视觉方向已确认，等待书面规范复核

## 1. 适用关系

本规范修订 `/oem-odm` 的视觉语言与版式规则，并继承 [`2026-09-20-vithelo-oem-odm-page-redesign.md`](./2026-09-20-vithelo-oem-odm-page-redesign.md) 中已经确认的信息架构、内容边界、数据契约、响应式、可访问性和测试要求。

两份规范冲突时，以本规范的视觉规则为准。被替代的旧规则包括：以 Ivory 作为页面主背景、连续交替图文模板、无投影图片，以及图片下方的三栏说明结构。

Nordicus 本地归档只作为视觉系统参考。不得复制其品牌、文案、图片、绿色配色、源代码或建筑业务逻辑。

## 2. 核心决定

页面采用“明亮编辑式 Nordicus 转译”方向：

- 当前 `/oem-odm` Hero 原样保留，不修改图片、文案、构图、尺寸或交互。
- Hero 以下的正文内容区以纯白 `#ffffff` 为页面背景，不使用米色、Ivory 或深色全宽面板；Inquiry Close 的既有图片场景收口不属于正文内容区。
- 以完整文案组和单张主图组织内容，不使用连续卡片、表格、信息台账或三栏字段式排版。
- 主图延续沉浸式大图策略，但不得出现黑色底板、黑色边距或黑色图片框。
- 标题与正文非必要不换行；不得通过 `<br>` 或拆分 `span` 人为制造碎行。
- 图片使用用户确认的紧贴边缘灰色柔光投影。
- VITHELO 继续使用 Graphite、Titanium 与克制 Optical light，不引入 Nordicus 的深绿色品牌色。

## 3. Nordicus 机制的正确转译

本次借鉴的重点不是大图或圆角本身，而是以下稳定机制：

1. 标签、标题、正文和操作属于同一个连续叙事组，共享左边界。
2. 一屏只有一个明确视觉主角；主图承担场景推进，不与多张等权图片竞争。
3. 标题优先使用短句，并通过可用宽度保持桌面单行；空间不足时才自然换行。
4. 留白来自内容比例、列间距和屏幕呼吸感，不来自米色填充、空卡片或无意义分隔线。
5. 图片与文案共同构成一个场景，不在图片下方追加“编号—标题—说明”三栏元数据。
6. 重复区块保持统一语法，但通过图片内容、左右关系和段落长度形成节奏，而不是每屏发明新模板。

## 4. 第二屏锁定设计

第二屏是 Hero 后的 `Custom Development` 总述屏，按已确认的视觉稿实施。

### 4.1 桌面构图

- 背景为纯白。
- 内容容器使用现有站点宽度体系；屏幕内部约为 `56% / 44%` 左右两列。
- 左侧为完整文案组，右侧为一张大圆角主图。
- 两列垂直居中，列间距用于形成呼吸感。
- 左侧顺序固定为：短横线与标签、标题、正文、主要操作与次要操作、剂型缩略图组。
- 右侧图片不得附加独立标题、图注栏或黑色背景。

### 4.2 文案层级

- 标签：`CUSTOM DEVELOPMENT`，使用 Precision 字体、大写和克制字距。
- 标题：`From brief to finished product.`，使用 Georgia 系列 Editorial 字体，桌面保持一行。
- 正文紧随标题，保持同一左边界，不独立放在屏幕另一侧。
- 操作继续路由至现有项目咨询和产品格式路径，不新增提交系统。
- 剂型缩略图只用于提示八种剂型属于同一开发能力场，不变成独立卡片。

### 4.3 图片与投影

- 主图使用 VITHELO 自有或已批准的无品牌项目图片。
- 圆角目标为约 `28px`，响应式收敛至约 `22px`。
- 投影使用用户确认的紧贴边缘灰色柔光：

```css
box-shadow:
  0 3px 11px rgb(34 38 39 / 28%),
  0 0 4px rgb(34 38 39 / 14%);
```

- 阴影四周可见，底部略深；不得扩大成大范围漂浮阴影，也不得加入描边。

## 5. 后续区块统一规则

既有信息架构保留，但视觉必须服从同一叙事语法。

### 5.1 Development Capabilities

- Sample Development、Formulation Direction、Dosage-Form Selection 继续分别说明。
- 每项能力由一个完整文案组与一张主图组成。
- 文案组顺序为标签、短标题、正文；说明不得被拆到远端独立列。
- 标题优先控制在 3–8 个英文单词，使桌面端尽量保持单行。
- 不在图片之后重复编号、标题和说明。

### 5.2 Dosage Formats

- 八种剂型继续保留在同一能力场中，Oral Films 不被单独隔离。
- 不使用八张等权卡片墙。
- 采用一个主叙事组配合连续剂型视觉带；所有剂型无需横向滚动即可访问。
- 文字标签清晰可读，图片只承担识别和节奏，不制造产品功效暗示。

### 5.3 Commercial Planning、Quality 与 Project Path

- MOQ 与 Lead Time 继续只解释变量，不给出固定承诺。
- Quality 只表达已验证的流程边界，不展示未核实认证。
- 十步项目路径通过顺序、留白和有限分隔表达，不做表格或十张卡片。
- 分隔线只在帮助理解顺序时出现；不得作为装饰重复铺满页面。

### 5.4 Packaging、Quote Preparation、FAQ 与 Inquiry Close

- 包装段落使用一张有明确主体的包装场景图，不做等权图库。
- Quote Preparation 合并重复内容，以短清单帮助买家准备首次沟通。
- FAQ 继续使用语义化 `details` / `summary`。
- Inquiry Close 沿用现有直接咨询路径，不新增内部表单。

## 6. 颜色与字体

- 页面主背景：`#ffffff`。
- 主文字：现有 Graphite `#191b1a`。
- 正文与次要信息：现有 Graphite Soft `#626762`。
- Titanium 与 Optical 只用于焦点、状态和少量细节，不形成彩色频道。
- 正文、导航、标签和操作使用现有 Precision 字体栈。
- 编辑标题使用本地稳定的 `Georgia, "Times New Roman", serif`，不新增依赖远程下载的字体资源。
- 不使用绿色、渐变按钮、彩色光晕或大面积 Ivory 表面。

## 7. 换行规则

- 文案写作优先缩短标题，而不是依赖 CSS 强制不换行。
- 桌面关键标题应在目标容器中保持单行；若无法保持，先改短文案或调整合理宽度。
- 不使用手工 `<br>`、不可断空格或拆字 `span` 控制视觉行。
- 平板和手机允许基于可用宽度自然换行，禁止横向溢出和裁切。
- 正文按自然段排版，不把同一句话拆成多个装饰性文本块。

## 8. 图片策略

- 每个主要场景最多一张主图；辅助缩略图只在有明确内容作用时出现。
- 图片裁切优先保留产品、包装或制造主体，避免空洞氛围图占据主位。
- 图片圆角与投影保持一致，不为不同区块创造多套图片样式。
- 不发布 Nordicus、Yile Health 或其他参考站的图片、Logo、名称和视觉资产。
- 不通过图片暗示未经验证的产线、认证、产能、客户、市场或功效事实。

## 9. 响应式与动效

- 桌面第二屏及三组 Development Capabilities 统一使用左侧完整文案组、右侧单张主图的两列结构，不左右交替；Dosage Formats、Project Path、FAQ 与 Inquiry Close 按其内容类型使用专属结构。
- 平板根据实际宽度收敛为单列，完整文案组始终先于其关联图片。
- 手机端图片、标题、正文和操作保持自然顺序，交互目标至少 `44px`。
- 动效只允许轻量进入揭示和图片响应，不使用视差、滚动劫持或持续漂浮。
- Reduced Motion 下直接显示最终状态，所有事实和操作始终可见。

## 10. 内容、组件与数据边界

- 继续通过 `src/content/schema.ts`、`src/content/demo/vithelo-b2b-site.ts` 与 `src/lib/content.ts` 提供验证后的页面内容。
- `src/app/oem-odm/page.tsx` 不直接定义业务事实。
- `VitheloOemOdmPage` 保持一个页面模式组件；只提取有明确用途的页面私有子组件。
- 不为一次性的视觉排列建立全站通用抽象。
- 不修改首页、导航、页脚、产品页、Insights 或 Contact。

## 11. 验收标准

- Hero 与当前已实现版本视觉一致，没有任何改动。
- Hero 后第一屏为纯白 `56% / 44%` 左右结构，并与确认稿一致。
- 第二屏标题在桌面目标视口保持单行，正文紧随标题且共享左边界。
- 主图圆角、裁切与参考投影一致，无黑色边距、黑色底板或图片描边。
- 页面不出现连续卡片墙、表格式三栏说明或图片下方重复元数据。
- 所有关键标题与正文非必要不换行，移动端无横向溢出。
- 八种剂型、十步路径、MOQ / Lead Time 条件边界、质量边界、FAQ 和询盘入口仍完整可达。
- 不新增未经验证的制造、认证、MOQ、交期、质量或市场声明。
- 六个验收视口与 Reduced Motion 状态下无 P0 / P1 视觉、可访问性或信息完整性问题。
- 定向单元测试、E2E、Lint、Typecheck 和 Build 通过后，才可提交视觉验收。

## 12. 明确不做

- 不复制 Nordicus 页面或源代码。
- 不修改当前 Hero。
- 不把 Hero 以下的内容区改成米色、绿色或深色全宽面板。
- 不使用黑色图片边距、硬阴影、玻璃拟态或卡片堆叠。
- 不重写与本次视觉修订无关的站点组件。
