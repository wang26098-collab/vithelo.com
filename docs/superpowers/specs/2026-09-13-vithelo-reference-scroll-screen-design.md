# VITHELO 第五屏参考滚动还原设计规范

日期：2026-09-13  
状态：待用户书面规范复核  
范围：首页第五屏 `#solutions`

## 1. 真实问题

当前第五屏把三张场景图组织成了一个居中的大卡片，虽然图片使用了固定定位，但视觉上仍然像“卡片在页面里移动”。用户提供的视频采用的是另一种空间关系：多个横向场景层构成连续页面，每个场景层本身是移动的裁切窗口，而该层对应的图片固定在视口坐标中。页面滚动时，窗口掠过图片，只有窗口覆盖到的位置能够看到该图片。

本轮不再修改旧卡片，而是完整替换第五屏的结构与视觉。

## 2. 已确认方案

采用“连续场景层 + 独立固定背景”的方案。

未采用的方案：

- 单一卡片内切换图片：这是上一版方案，空间关系与参考视频不同。
- 把首页所有八屏都改成固定背景：范围过大，并会破坏已锁定的 Hero 与其他已接受屏幕。

“一比一还原”指参考视频的滚动语法、画面占比、覆盖关系与节奏；不得复制参考站的品牌、建筑素材、文案或业务内容。

## 3. 单屏构成

第五屏是一个连续的长叙事区，由以下部分组成：

1. **白色引导区**：保留充足留白，以短标题和一段说明建立“从使用场景开始定义产品”的任务。
2. **场景层 01 — Evening Routines**：说明使用时刻与期望体验。
3. **场景层 02 — Everyday Wellness**：说明受众与日常使用语境。
4. **场景层 03 — Active Days**：说明携带、频率和使用方式如何影响剂型选择。
5. **白色收束区**：以简短桥接语自然进入第六屏剂型展示，不增加新 CTA。

三段内容承担不同叙事任务，不重复第五屏内部信息，也不重复制造、定制能力、剂型墙和询盘屏的任务。

## 4. 视觉结构

- 每个场景层在桌面端约占一个视口高度，宽度接近页面全宽，只保留与参考视频相同量级的窄边距。
- 场景层使用明确圆角；桌面 32–40px、平板 24–32px、手机 18–20px，并继续服从首页圆角令牌。
- 相邻场景层直接接触或轻微覆盖，不出现上一版大面积白色卡片间隙。
- 图片填满窗口，保持电影感横向构图，使用冷 Ivory、Graphite 与低饱和光线；不引入绿色营养频道。
- 文案位于图片左下区域，采用小标题、短说明和克制的序号。图片上只保留必要遮罩以保证对比度。
- 不显示分页数字、左右箭头、轮播点或横向轨道。

## 5. 滚动模型

桌面和平板使用浏览器原生纵向滚动：

1. 每个场景层作为独立的移动裁切窗口，随文档向上移动。
2. 该场景层对应的图片固定在相同的视口坐标中。
3. 图片只能通过自己所属场景层的裁切范围显示；窗口外不可见。
4. 下一场景层从视口底部进入，并覆盖上一场景层；两层交界处允许同时看到两张各自匹配的图片。
5. 场景层完全离开视口后，其固定图片不再可见，也不覆盖后续内容。
6. 禁止滚动劫持、强制吸附、程序化滚动和滚轮速度修改。

验收时必须证明：滚动一段距离后，场景层的视口位置发生等量变化，而该层图片的视口位置保持不变；相邻两层同时可见时，各自只显示自己的图片。

## 6. 响应式与无障碍

- 宽度大于 760px：启用完整固定图片与移动裁切窗口效果。
- 宽度不大于 760px：保持相同圆角场景层和内容顺序，但图片随内容自然滚动，避免移动端固定背景的浏览器兼容与性能问题。
- Reduced Motion：显示完整静态纵向内容，不依赖动画才能读取文案或看到图片。
- 无 JavaScript：内容、图片和进入第六屏的路径保持可用。
- 文本对比度、键盘顺序、语义标题结构和 200% 文本缩放不得退化。

## 7. 实现边界

- 只替换第五屏组件及其定向样式和测试。
- Hero、导航和其他七屏的既有屏高与全局上下/左右内间距保持不变。第五屏可为容纳引导区、三个整屏场景层和收束区而增加自身滚动长度，这是本轮唯一允许改变的首页屏高。
- 沿用现有经过内容层验证的三个场景记录；不在页面组件中硬编码产品事实。
- 不新增外部动画依赖。优先使用 CSS 固定定位、裁切与层级关系表达效果。
- 不修改用户正在进行的产品页、内容模型或其他无关工作树变更。

## 8. 验收标准

- 第五屏不再呈现为居中的单一卡片。
- 桌面 1440、1280，平板 1024、768 均能看到近全宽、连续的圆角场景层。
- 任一场景层滚动至少 160px 时，对应图片的视口位置变化不超过 1px。
- 相邻场景层交界处同时显示两张不同且匹配的图片，没有串图、灰色占位或大块空白。
- 第五屏结束后，第六屏可自然到达，固定图片不会泄漏到后续屏。
- 手机 390、375，Reduced Motion 和无 JavaScript 模式内容完整可读。
- 首页几何锁定契约、定向单元测试、六视口 E2E、类型检查与生产构建通过。
