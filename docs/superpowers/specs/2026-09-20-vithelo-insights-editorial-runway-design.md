# VITHELO Insights 编辑长廊设计规范

日期：2026-09-20  
状态：结构、动效与内容边界已确认，待用户审阅书面规范后进入实施

## 1. 真实问题

当前 `/insights` 能够列出 10 篇买家指南，但页面仍是通用 Hero、主题标签和文字索引，缺少与 VITHELO 当前首页相匹配的视觉重量，也没有把知识内容组织成一条连续、可记忆的编辑叙事。本轮只改造 Insights 列表页，把用户指定的 Nordicus `Solutions` 页面中“沉浸式 Hero、圆角浅色内容层、Red Edge Tower 图文关系”转译成 VITHELO 自己的知识长廊。

参考页仅用于拆解视觉与交互机制。不得复制 Nordicus 的品牌、文案、建筑图片、客户标识、绿色景观色彩或页面代码。

## 2. 目标与边界

### Must

- 目标路由仅为 `/insights`。
- 保留现有 10 篇已发布文章及其顺序、分类、标题、摘要、日期和详情链接。
- 使用深色沉浸 Hero、冷象牙圆角内容层以及连续 10 组左文右图大版式。
- 文章图片通过 Zod 内容合同和本地内容适配器进入页面，不写死在路由或组件中。
- 每张当前文章图片均明确保持 `DEMO_ONLY`，并提供有意义的替代文本。
- 桌面、平板、手机、键盘、无 JavaScript 与 Reduced Motion 状态均可完整使用。
- 不引入滚动劫持、横向轮播、自动切换或鼠标跟随。

### Should

- 让 Hero 与内容层的衔接接近参考页的“暗色场景压住画面、浅色纸张从下方覆盖”体验。
- 10 个单元保持统一结构，形成稳定的编辑节奏，不因连续展示而退化成普通卡片网格。
- 让买家能在大图叙事与快速扫描之间取得平衡：编号、分类、标题、摘要、更新时间和入口必须在每个单元中直接可见。

### Could

- 后续在获得正式图片与内容审核结果后，替换单篇文章的 `DEMO_ONLY` 视觉。
- 后续为主题索引增加真实筛选能力，但本轮不实现筛选。

### Won't

- 不修改 `/insights/[slug]` 文章详情页。
- 不改导航结构、其他内部页面、首页或已接受屏幕。
- 不重写文章正文，不改变文章顺序，不新增未经核验的功效、剂量、认证、产能、MOQ、交期、价格或法规结论。
- 不把主题索引伪装成客户 Logo、合作背书或认证标识。
- 不新增 CMS、搜索、分页、筛选、分析、表单提交或外部内容服务。
- 不复制参考站的图片、字体、品牌、文案、颜色、代码或可识别装饰细节。

## 3. 参考机制的 VITHELO 转译

| Nordicus 参考机制 | VITHELO 转译 |
| --- | --- |
| 深色建筑场景 Hero | 现有 VITHELO 营养制造影像加石墨遮罩 |
| 导航悬浮在场景上 | 继续使用现有 VITHELO 固定导航与 `split-hero` 主题 |
| 白色大圆角内容层覆盖 Hero 底部 | 冷象牙编辑纸张层覆盖 Hero 底部，不改变全站导航 |
| 客户 Logo 横向排列 | 5 个 Knowledge Areas 静态主题索引，不表达背书 |
| “Our Projects” 编辑引言 | Insights 知识长廊导语，解释文章承担的买家决策任务 |
| “Red Edge Tower” 左文右图项目单元 | 10 篇文章统一使用左侧信息、右侧大图结构 |
| 黑色序号标签 | 石墨色 `01–10` 章节编号，用于定位而非分页 |
| 建筑项目说明 | 现有文章分类、内容格式、更新时间、摘要和阅读全文入口 |

## 4. 页面结构

### 4.1 沉浸式 Hero

- Hero 占据主要首屏高度，导航保持悬浮于影像上方。
- 继续使用现有内容：
  - Kicker：`INSIGHTS`
  - H1：`Practical guidance for product decisions.`
  - Copy：`Buyer guides connect format, formula, packaging and manufacturing questions without turning unverified claims into proof.`
- Hero 使用现有 VITHELO 本地影像并增加深石墨遮罩，确保导航和文字达到可读对比度。
- 画面只建立 VITHELO 的营养制造氛围，不出现 Nordicus 建筑、标识或可识别素材。

### 4.2 圆角内容层

- 冷象牙内容层覆盖 Hero 底部，桌面使用明显但克制的大圆角。
- 内容层必须保持正常文档流；覆盖关系只通过负外边距或等价布局实现，不使用固定定位卡住滚动。
- 手机端减小圆角与重叠距离，避免首屏文字和内容入口互相遮挡。

### 4.3 Knowledge Areas 主题索引

- 在内容层顶部横向展示现有 5 个主题：Product Development、Dosage Formats、Packaging & Launch、Manufacturing & Quality、Buyer Guides。
- 本轮为静态信息带，不增加尚未实现的筛选状态或可点击假交互。
- 索引使用细线与小号大写字，替代参考页的 Logo 行，不表达客户关系。

### 4.4 编辑引言

- 主题索引下方设置一组短引言，承担参考页 `Our Projects` 的叙事作用。
- 引言只说明这些文章帮助买家梳理产品、剂型、包装、制造和询盘决策，不加入 VITHELO 能力或结果承诺。
- 标题与正文从现有 Insights 内容语义中提炼；最终英文文案必须通过内容合同进入组件。

### 4.5 十篇文章长廊

- 10 篇文章严格按现有数据顺序渲染。
- 每篇桌面端均为一致的左文右图双栏：左侧约 `42%`，右侧约 `58%`。
- 左侧包含：
  - `01–10` 章节编号；
  - 文章分类；
  - 内容格式与更新时间；
  - 文章标题；
  - 完整现有摘要；
  - 明确的 `Read insight` 入口。
- 右侧为大比例主题影像，使用低圆角或与内容层一致的边缘处理；不做浮动卡片堆叠。
- 每个单元之间以大留白和细分隔线建立节奏。所有单元保持左文右图，不左右交替。
- 标题链接和显式 CTA 均指向现有 `/insights/[slug]`，不改变详情页行为。

## 5. 视觉系统

- 背景继续使用 VITHELO 的 cold Ivory、Graphite 与 Titanium。
- Hero 使用 Graphite 遮罩；文章主体不转为绿色营养频道。
- 暖色只允许作为极少量提示信号，例如编号或焦点状态，不形成大面积橙色装饰。
- 标题继续使用项目现有展示字体，正文继续使用现有精密字体系统；不引入 Nordicus 字体。
- 页面不使用通用圆角卡片网格、厚重投影或玻璃拟态堆叠。主要视觉张力来自影像尺度、负空间、细线和明暗转换。
- 图片必须保持营养制造、剂型、包装或项目准备的语义，不把抽象素材解释成已核实证明。

## 6. 内容与数据流

- `B2BInsightArticleSchema` 增加必需的列表页 `media` 记录，至少包含：
  - `src`：站内 `/media/...` 路径；
  - `alt`：与文章主题一致、但不构造生产事实的英文替代文本；
  - `status`：当前固定为 `DEMO_ONLY`。
- `B2BInsightsPageSchema` 增加短编辑引言字段，避免把公开英文文案写死在 React 组件中。
- `vitheloB2BInsightsPage` 为 10 篇文章配置现有本地图片；允许不同文章复用相关素材，但优先保证主题匹配和视觉变化。
- `localContentAdapter` 的公开读取方式保持不变；文章详情页即使获得新增 `media` 字段，也不改变当前渲染。
- 所有公开页面仍只显示 `VITHELO`，不暴露参考资料来源公司的名称、Logo 或原始品牌。

## 7. 组件边界

- `src/app/insights/page.tsx` 继续负责读取站点与 Insights 内容，并使用现有页面框架。
- `VitheloInsightsPage` 负责 Hero、主题索引、编辑引言和文章长廊的语义结构。
- 如需要客户端视口揭示，新增一个职责单一的 Insights reveal 包装组件；它只管理可见状态，不持有内容数据。
- 样式优先进入 Insights 专属 CSS module，避免继续扩张已承载多类页面的 `vithelo-b2b-pages.module.css`。
- 不为单一路由建立可配置页面生成器或跨页面抽象。

## 8. 动效与交互

- 首次进入时，Hero 背景从轻微放大状态平滑回落至原尺寸；标题、说明按短延迟依次淡入上移。
- 圆角内容层随原生页面滚动自然进入，不固定、不吸附、不改变滚轮距离。
- 文章单元进入视口时做一次性同向揭示：图片先显现，文字随后出现，语义为 `ORIENT / RELATE`。
- hover 或 `:focus-visible` 时，图片仅轻微放大，标题下划线与箭头响应；不让整块区域变成缺少语义的大按钮。
- 所有 CTA 最小触控目标不小于 44px，并保留清晰焦点样式。
- 无 JavaScript 时内容保持可见，链接正常工作。
- `prefers-reduced-motion: reduce` 下关闭位移、缩放、延迟和过渡，直接显示最终状态。

## 9. 响应式行为

- 大桌面：Hero 维持沉浸比例；文章双栏约 `42 / 58`；内容层在宽屏中保留足够外边距。
- 平板：文章继续双栏但降低间距和字号，图片保持主要视觉重量。
- 手机：每篇改为图片在上、文字在下；编号、分类、标题、摘要、日期和 CTA 全部进入正常文档流。
- 主题索引允许自然换行，不形成横向滚动条。
- 所有验收视口不得出现裁切、覆盖、导航遮挡、文字溢出或页面级横向滚动。

## 10. 状态与失败行为

- 图片加载失败时，仍显示文章文字、链接与 `DEMO_ONLY` 状态，不让整篇文章消失。
- 没有 JavaScript 时，Hero、主题索引和 10 篇文章保持完整顺序。
- Reduced Motion 直接显示最终布局和内容。
- 内容适配失败继续沿用现有路由级错误处理，不新增伪造文章或回退事实。
- 空文章集合不是当前允许的数据状态；Zod 合同与测试继续确保 10 篇已发布内容存在。

## 11. 测试与验收

### TDD 顺序

1. 先增加失败组件测试，要求页面呈现 Hero、5 个主题、10 个编号文章单元、10 张有替代文本的图片和正确链接。
2. 运行定向测试并确认失败原因是新结构尚未实现，而不是测试配置错误。
3. 再增加内容合同与演示数据，令合同测试通过。
4. 最后实现组件、样式和动效，令组件测试通过。

### 自动验证

- 定向单元测试：Insights 组件、内容合同、公开身份与文章链接。
- 定向 E2E：六个验收视口、键盘焦点、Reduced Motion、无横向溢出、Hero 与圆角内容层关系。
- 运行相关文件 ESLint、`pnpm.cmd typecheck`、定向 unit、定向 E2E 和 `pnpm.cmd build`。
- 完整回归如仍含项目已记录的旧断言失败，必须与本轮新增失败分开记录，不得宣称全绿。

### 视觉验收

- 首屏明确呈现暗色沉浸 Hero 与浅色圆角内容层的层叠关系。
- 10 篇文章全部以统一左文右图的大图文单元呈现，不退化成列表或卡片网格。
- 页面连续滚动时保持稳定而不单调，图片和文字不抢夺可读性。
- 不出现 Nordicus 品牌、建筑素材、Logo、绿色视觉或可识别文案复制。
- P0 = 0、P1 = 0 后，由用户完成 `/insights` 最终视觉确认。

## 12. 成功标准

用户进入 `/insights` 后，能够在第一屏确认这是 VITHELO 的制造知识入口，并在连续滚动中依次理解 10 篇文章各自解决的买家问题。页面既保留参考站的沉浸式 Hero、圆角内容层和稳定图文节奏，又保持 VITHELO 的品牌、内容证据边界和 B2B 询盘定位。
