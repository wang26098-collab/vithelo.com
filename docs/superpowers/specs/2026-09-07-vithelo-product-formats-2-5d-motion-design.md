# VITHELO 首页第六屏 2.5D 动效升级规范

日期：2026-09-07  
状态：方案 A 已确认，等待书面规范复核

## 目标与范围

保留当前 `06 · Product Formats` 的标题、八张产品图、双列错位排版、移动端单列和八个产品详情链接，只升级该屏的动效机制，使其更接近 Lusion `Featured Work` 的空间感与交互反馈。其他七屏不修改。

实现采用 DOM、CSS 与现有 Motion 能力完成 2.5D 高还原效果；不复制 Lusion 代码、素材或品牌，不引入 WebGL 深度图，不改变浏览器原生滚动。

## 参考机制与当前差异

对参考录屏和 Lusion 当前页面代码的核对表明，其 `Featured Work` 并非普通淡入：

- 标题逐字从裁切容器下方进入，每个字符带约 `10deg` 初始旋转和错峰节奏。
- 项目媒体按左右列从相反方向进入，初始水平位移约为视口宽度的 10%，并带轻微旋转。
- 项目视觉使用持续更新的滚动速度、指针位置和景深参数产生形变、涟漪与视差。
- 项目名称先经历短暂字符扰动，再稳定为真实名称；辅助文字在悬停时产生纵向滚动反馈。

当前 VITHELO 第六屏只有卡片透明度进入和图片轻微纵向位移，因此缺少参考效果最明显的逐字翻入、左右斜入、速度形变、指针视差与文字反馈。

## 已确认方向：方案 A

名称：`Featured Format Wall · 2.5D Motion`

使用渐进增强的 2.5D DOM 动效还原参考网站的运动逻辑，同时保留 VITHELO 冷象牙、石墨、钛金属与暖珊瑚视觉体系。

### 1. 标题进场

- `One system. Eight expressions.` 按字符拆分为独立的裁切单元。
- 字符初始位于自身高度下方并旋转 `8–10deg`，进入时使用强减速曲线逐个翻起。
- 字符错峰间隔控制在 `18–24ms`，整段在约 `900–1200ms` 内完成。
- 说明文字按行从下方揭示，延后约 `160ms`，不使用透明度模糊。
- 标题只播放一次；向上回滚时不反复抖动重播。

### 2. 卡片进入

- 左列从左下方进入，右列从右下方进入；初始水平位移为 `6–9vw`，纵向位移为 `40–64px`。
- 初始旋转不超过 `3deg`，进入后归零。
- 不再把透明度作为主要效果；内容始终可辨认，运动感来自方向、旋转与强减速。
- 每张卡片独立进入，不让整组同时弹出，也不改变当前双列错位排版。

### 3. 滚动速度响应

- 客户端增强器在 `requestAnimationFrame` 中读取原生滚动速度并进行平滑插值。
- 仅对当前视口附近的媒体更新 CSS 变量；速度值必须限幅，停止滚动后自然回到零。
- 图片在媒体裁切框内产生最多约 `12px` 的纵向惯性、`0.8deg` 的轻微倾斜和不超过 `1.5%` 的拉伸，形成接近参考网站的弹性空间感。
- 不移动正文布局，不修改滚动位置，不使用滚动吸附或滚轮劫持。

### 4. 鼠标 2.5D 视差

- 桌面精确指针设备上，鼠标在媒体内移动时，图片向相反方向偏移，最大 `12px × 8px`。
- 媒体层具有极轻微 `rotateX / rotateY` 与高光响应；离开后平滑回中。
- 卡片本体不浮成带阴影的通用卡片，仍保持平面编辑式作品墙。
- 触屏设备不启用指针视差。

### 5. 名称与悬停反馈

- 项目首次进入时，名称执行约 `420–600ms` 的字符解码，随后稳定显示真实名称。
- 解码只改变视觉文本，标题语义通过稳定的 `aria-label` 保留；不设置 `aria-live`。
- 悬停或键盘聚焦时，箭头移动与字符滚动反馈控制在局部，不让其他项目整体变暗。
- 点击区域仍是当前完整图片与名称链接。

## 组件边界

- 服务端 `DosageSection` 继续负责八项语义结构、图片、链接和稳定文本。
- 新增一个只服务第六屏的轻量客户端动效增强器，负责 IntersectionObserver、滚动速度、指针位置和字符解码。
- 动效状态通过 `data-*` 属性与 CSS 自定义属性传递，不进入内容数据层，不新增产品状态或路由状态。
- 所有监听器在组件卸载时清理；不可见卡片停止逐帧更新。

## 响应式与降级

- 桌面：完整启用逐字翻入、左右斜入、滚动速度响应、指针视差和文字解码。
- 平板：保留逐字翻入、左右斜入和低强度滚动响应，关闭依赖精确鼠标的效果。
- 手机：卡片改为纵向进入，滚动速度形变减半，不启用指针视差；保持单列自然滚动。
- 浏览器不支持相关能力时，退化为内容直接可见加基础进入动画，不影响链接。
- `prefers-reduced-motion: reduce` 下不拆字播放、不解码、不斜入、不视差、不速度形变，所有内容直接显示为最终状态。
- 键盘焦点、触控目标、DOM 阅读顺序和八项完整性保持不变。

## 性能边界

- 不引入 WebGL、深度图、Canvas 或新的第三方动画依赖。
- 每帧只读一次滚动位置，布局读取与样式写入分离；速度与视差更新只作用于第六屏可见媒体。
- 不对 `top`、`left`、尺寸等布局属性做逐帧动画，优先使用 `transform` 与 CSS 变量。
- 在六个验收视口检查长任务、掉帧、横向溢出和导航遮挡。

## 验收标准

- 进入第六屏时，第一眼可见标题逐字翻入而不是整体淡入。
- 左右列项目从相反方向带轻微旋转进入，节奏接近参考网站。
- 快速与慢速滚动时，媒体具有可感知但不夸张的惯性形变；停止后平稳归零。
- 桌面鼠标移动能产生明确的 2.5D 图像视差，离开后恢复。
- 项目名称完成一次短暂解码并稳定为正确的八种剂型名称。
- 排版、产品图、文案、链接、顺序和其他七屏不发生变化。
- 375、390、768、1024、1280、1440 宽度无裁切、重叠或横向溢出。
- Reduced Motion 下八项内容始终完整可见且可操作。
